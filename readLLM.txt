## 1. 全体方針と制約（厳守事項）

- **ビルドツール不要のブラウザ直接実行構成**
  - バンドラ（Vite/Webpack等）や TypeScript は使用しません。
  - **ES Modules (`import` / `export` / `type="module"`) は使わないこと。** HTMLを `file://` で直接開いた際にCORSエラーで動かなくなるのを防ぐため、クラシック `<script>` タグによるグローバル共有構成を採用しています。
- **3Dモデルの注意点**
  - Three.js は CDN（r128）を優先し、オフライン時は `./three.min.js` にフォールバックします。
  - `./GLTFLoader.js` + `./models.js` による GLB 3Dモデル読み込みはブラウザのCORS制約を受けるため、`file://` 直開き時は箱（Box）表示にフォールバックします（ローカルHTTPサーバー経由では正常に表示されます）。
- **外部ファイルの互換性維持**
  - `items.js` / `models.js` / `help.js` / `excel-export.js` は既存のグローバル変数・関数・DOM IDを直接参照するため、公開シンボル名や主要DOM IDを勝手に変更・削除しないでください。

## 2. ファイル構成と読み込み順

`index.html` での読み込み順には意味があります。順序を変えないでください。

### `<head>` 内
1. **`recovery.js`**（約210行）
   - エラーログパネル（右下に常駐、`Ctrl+Shift+D` で開閉）および診断・復旧モーダル。
   - アプリ本体が起動クラッシュしても単体で動作するよう、他のスクリプトより先に独立ロードします。
2. **Three.js / `GLTFLoader.js` / `models.js`**
   - 3D描画ライブラリとGLBモデル対応表 (`window.OP_MODELS`)。
3. **`style.css`**（約250行）
   - テーマ変数（ダーク/ライト）、印刷用スタイル（`@media print`）、2D/3D UI・モーダル全般のスタイル。

### `<body>` 内
1. **テーマ即時初期化インラインスクリプト**（`index.html` 内）
   - 画面描画前のチラつきを防ぐため、`localStorage('op_theme_v1')` とOS設定を確認して `body.light-mode` を即座に付与します。
2. **静的HTML骨組み**（`index.html` 内）
   - ヘッダー、左右サイドバー、キャンバス領域、ステータスバー、コンテキストメニュー、各種モーダル。
3. **`items.js`**（既存外部ファイル）
   - 家具・構造・備品・OA用品カタログ定義（`FURN_DEFS`, `STRUCT_DEFS`, `GENBA_DEFS`, `OFFICE_DEFS`）。
4. **`editor-2d.js`**（約420行）
   - 2Dキャンバスの状態、描画（特殊備品シンボル・配線端点アイコン統合）、ヒットテスト、マウス操作、ズーム/パン、部屋外管理、ルーラー、表示設定トグル。
5. **`editor-ui.js`**（約370行）
   - レイヤー管理、サイドバー構築＆検索、配線パネル、右プロパティパネル、コンテキストメニュー、キーボードショートカット、物のリスト、左右パネル折りたたみ、バージョン情報バー。
6. **`storage.js`**（約440行）
   - JSONバリデーション (`validateState`)、状態適用 (`applyState`)、ブラウザ自動保存、10スロット保存管理、読込前バックアップ、共有URL（gzip圧縮）、テンプレート読込、高解像度PNG画像保存、Undo/Redo履歴、起動シーケンス。
7. **`view3d.js`**（約440行）
   - ヘッダーの「2D編集 / 3D表示」切替タブ、Three.js 3Dシーン構築、壁・ドア開口生成、高さ推定・卓上アイテム自動乗せ、3D人物リグと9:00〜18:00在室シミュレーション、3Dテーマ同期。
8. **`help.js` / `excel-export.js`**（既存外部ファイル）
   - ヘルプ表示・テンプレート導線・Excel出力。

座標系（2D vs 3D の違いに注意）
2D座標（メートル単位）
部屋の左上角が (0, 0)、右方向が +x、下（奥）方向が +y。
部屋の外側も配置可能（負座標や > roomW / roomH を許容）。workMargin によりキャンバスの表示余白が自動拡張される。
オブジェクトの (x, y) は 未回転時の左上角。回転 rot は中心基準で 時計回り（度）。
3D座標（Three.js・メートル単位）
2Dの (x, y) が 3Dの (x, z) 平面に対応し、高さ方向が +y。
オブジェクト中心は (o.x + o.w/2, elev + h/2, o.y + o.h/2)。
回転方向が2Dと逆のため、3D側では rotation.y = -THREE.MathUtils.degToRad(o.rot) を使用する。
デフォルトレイヤーID（editor-ui.js）
1: 家具 / 2: 構造 / 3: 電気配線 / 4: LAN / 5: その他 / 6: 人物スポーン
persons 配列は旧2D人物シムの名残だが、既存JSONの後方互換のため読み込み・保持のみ行っている。

6. 開発・改修時の重要ルール
変更の保存・履歴・余白更新はすべて scheduleSave() を経由する
家具の移動・追加・削除・プロパティ変更時は必ず draw(); updateCounts(); scheduleSave();（または必要なUI更新）を呼んでください。
scheduleSave() 1つで以下の4つが連動します：
部屋外配置に応じた余白自動拡張 (opEnsureMargin) と外配置カウント更新
localStorage へのデバウンス自動保存 (saveLS)
スロット未反映バッジの更新 (updateCurrentSlotBadge)
Undo/Redo履歴のデバウンス記録 (_opHistoryNote)
データの読込・全クリアは opWithBackup(label, fn) と validateState() を通す
外部JSONやURLの適用は applyState() に集約されており、不正データによる既存作業の破壊を防ぎます。
objects / lines に新しいプロパティを追加する場合は、storage.js の validateState() でのサニタイズ許可リスト（および必要なら view3d.js の convert2Dto3D()）を必ず更新してください。
新規モーダル・ダイアログを追加する場合
.modal-overlay と .show クラスで開閉する設計にするか、editor-ui.js の opModalOpen() のセレクタへ追加してください。これを怠るとモーダル入力中に Delete / R / 矢印キーなどのキャンバス用ショートカットが誤爆します。
3Dビュー中の編集禁止
body.view3d-mode クラス付与中は、CSS（pointer-events: none）と opEditKeysAllowed() によって2D側の操作が無効化されます。3D側から直接 objects を書き換える仕様を追加しない限り、この分離を維持してください。
バージョン更新時
editor-ui.js 先頭の APP_VERSION と APP_UPDATED を更新すると、フッター・診断情報・3Dビューのヒント表示に自動反映されます。
